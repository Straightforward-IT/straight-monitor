# Frontend UI system

The default controls in Straight Monitor are composed from theme tokens and shared Vue components. New work should use these controls instead of adding page-local `primary-button`, `secondary-button`, `icon-button`, or global `button` styles.

## Runtime colours and readability

- `frontend/Straight-Monitor/src/utils/appearance.js` is the source of truth for selectable accents: display name, hex value, RGB value, and legible foreground colour.
- `frontend/Straight-Monitor/src/stores/theme.js` applies the active values to the document root. Components consume CSS variables rather than hard-coded accent values.
- `frontend/Straight-Monitor/src/assets/styles/theme.scss` owns semantic runtime tokens: action states, control radius, focus ring, disabled controls, and modal layers.
- `global.scss` remains the Sass-variable compatibility layer injected by Vite. Do not import it again in a component style block; use `theme.scss` only when a direct import is genuinely needed.

The primary-action foreground must use `--on-action-primary` (or the legacy alias `--primary-contrast`), never a literal white value. This keeps all selectable accents readable.

Use `--action-accent-text` for accent-coloured text on surfaces, outlined actions, and ghost actions. It is resolved separately from the fill colour (`--primary`); light accents otherwise have insufficient text contrast on light surfaces. Both light and dark text variants are defined in `appearance.js`.

Use `--status-danger-text`, `--status-success-text`, and `--status-warning-text` for error/success/warning messages. Their dark-mode values differ from the action fill colours as well. `--status-warning` supplies warning borders and tinted backgrounds. Custom location colours should mark borders/backgrounds, not replace readable `--text` labels.

## Default controls

| Component | Use it for |
| --- | --- |
| `AppButton` | Primary, secondary, outlined, ghost, and destructive text actions. Supports `sm`, `md`, `lg`, `loading`, `disabled`, and `block`. |
| `AppIconButton` | Icon-only actions. `label` is required and supplies the accessible name and default tooltip. |
| `AppTextInput` | Native text, URL, password, and numeric inputs with common disabled and focus treatment. Supports `.trim` and `.number`, preserves empty numeric values, and defers updates during IME composition. |
| `AddressAutocomplete` | Reusable free-text address combobox. Accepts local labels and an optional asynchronous `searchSuggestions(query)` provider; the caller owns its API and maps results to strings. Supports `v-model`, disabled state, keyboard selection, and an accessible teleported list. |
| `AppSegmentedControl` | Mutually-exclusive visible choices with radio semantics, one tab stop, arrow-key navigation, and Home/End. Disabled options are skipped. |
| `ModalFrame` | Default modal shell with escape/backdrop handling, scroll locking, and shared close/PDF controls. It does not currently provide a focus trap or focus restoration. |

Button copy remains at the feature boundary because it carries product meaning. Prefer short verbs (`Speichern`, `Abbrechen`, `Entfernen`) and use the same verb for the same action across one workflow. Do not put feature-specific text into a generic component.

## Migration rules

1. Replace a local action-button class with `AppButton` before changing its visual layout.
2. Replace icon-only native buttons with `AppIconButton` and provide a descriptive `label`.
3. Use `ModalFrame` before custom backdrop, escape, close, z-index, or scroll-lock code is added.
4. Keep layout-specific spacing in the feature. Shared colour, state, focus, disabled, and typography rules belong in the UI component or semantic token layer.
5. Do not add a global bare `button` rule: legacy views still contain many native buttons and must be migrated in bounded slices.
6. `ModalFrame` forwards its class/style attributes to a teleported dialog element that does not carry the caller's CSS scope. Set frame variables through a forwarded `style`, or a narrowly namespaced `:global(.feature-modal)` rule, including responsive overrides. Keep slot-content styling scoped. Associate submit buttons in `#footer` with a uniquely identified body form via `form` so native validation and Enter submission still work.

Example:

```vue
<AppButton :loading="saving" @click="save">Speichern</AppButton>
<AppButton variant="secondary" @click="close">Abbrechen</AppButton>
<AppIconButton label="Ansicht aktualisieren" @click="refresh">
  <font-awesome-icon icon="fa-solid fa-rotate" />
</AppIconButton>
```
